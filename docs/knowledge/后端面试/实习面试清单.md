## 一、Java 基础

### 1. `==` 和 `equals` 的区别

在 Java 中，`==` 比较的是地址，`equals()` 比较的是内容（前提是类重写了它）。

`==` 用来比较两个变量是否指向同一块内存地址。

- 对 **基本类型** 来说，`==` 比较的是值；
- 对 **引用类型** 来说，比较的是对象引用，也就是内存地址是否相同。

而 `equals()` 是 Object 类的方法，默认实现与 `==` 相同，也是比较地址。但许多类（如 String、Integer）重写了 `equals()`，改为比较内容。  
因此，在大多数业务代码中，`equals()` 是用来判断两个对象内容是否相等的。

**String 的特殊性：**  
字符串字面量会放入字符串常量池，相同字面量共用一个对象，所以

```java
String a = "abc";
String b = "abc";
a == b        // true
```

但使用 `new String("abc")` 时会在堆中新建对象，因此

```java
String c = new String("abc");
a == c        // false
a.equals(c)   // true
```

### 2. String 为什么不可变？

`String` 不可变，不是因为 `final` 一词神奇，而是因为它的内部实现从语法、封装到设计都禁止修改原始内容。这种设计能带来安全性、线程安全和性能优化等多方面好处。

`String` 之所以不可变，是语言层面与设计层面的共同结果。  
首先，`String` 类被 `final` 修饰，无法被继承；其次，其内部存储字符的数组 `value` 也是 `private final`，并且没有任何方法能直接修改这段数组的内容。

需要注意，`final` 修饰引用类型时，只能保证**引用地址不可变**，并不能阻止对象内部状态改变。但 `String` 通过**私有化字段 + 无修改方法**的方式，彻底封死了修改通道。  
因此每次字符串拼接、替换、截取，都是创建一个新对象返回，原对象保持不变。

这种设计带来的好处是：

- **安全性**：字符串常用于类加载、网络、文件路径等关键位置，不可变防止被篡改；
- **线程安全**：多线程可安全共享；
- **性能优化**：支持字符串常量池与哈希值缓存。

## 九、面试心态调整

### 记住这几点：

1. **面试官不是来刁难你的**

   - 他们想看到的是：你的学习能力、思考方式、沟通能力
   - 不会的问题，诚实说"不太清楚"，然后说说你的理解

2. **实习 ≠ 要求你啥都会**

   - 你的竞争对手也是学生，大家水平差不多
   - 你已经准备了这么多，已经比很多人强了

3. **面试是双向选择**

   - 不是只有他们在选你，你也在选公司
   - 放轻松，把它当成一次交流

4. **第一次面试很重要，但不是唯一机会**
   - 即使挂了，也是一次宝贵的经验
   - 每次面试都会让你更从容



## 十、学习建议

### 每天的时间分配（如果还有 2 周准备时间）

**第 1 周**：

- 上午（3 小时）：看知识点，理解原理
- 下午（2 小时）：刷算法题
- 晚上（2 小时）：准备项目介绍，模拟讲解

**第 2 周**：

- 上午（3 小时）：复习标记的 30 个核心知识点
- 下午（2 小时）：继续刷题
- 晚上（2 小时）：模拟面试，对着镜子讲

### 快速记忆技巧

1. **用自己的话总结**

   - 不要死记硬背笔记上的原话
   - 用"通俗比喻"来理解（比如：HashMap 就像一个有很多格子的柜子）

2. **画图辅助记忆**

   - HashMap 的结构：画数组+链表
   - Spring Bean 生命周期：画流程图

3. **讲给别人听**

   - 找室友、同学，给他们讲一遍
   - 讲出来才是真的懂

4. **重点知识做卡片**
   - 正面：问题
   - 反面：答案
   - 每天早上翻一遍
